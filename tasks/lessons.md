# 經驗與防錯檢查

## 2026-09-17：輸出範圍與模型分支

- 類型：需求理解錯誤。
- 失敗模式：將影片配音的背景情境延伸成「必須合成影片」，並以線性流程暗示 TTS 後必須再做 VC。
- 偵測訊號：使用者已明確說明只要練習聲音轉換並取得 WAV。
- 預防規則：以使用者明確的最終產物定義驗收；TTS 與 VC 各有獨立輸入與輸出。
- 主動檢查：交付前搜尋「合成影片」「TTS → VC」，確認它們沒有被列為必要功能；檢查是否誤把免訓練推論標成已訓練。

## 2026-09-17：執行機假設與新手流程

- 類型：錯誤環境假設、缺少操作走讀。
- 失敗模式：將開發機當成正式訓練機；改完開頭卻仍在後文保留 4 GiB 限制；加入更多頁面與比較步驟後，反而造成重複審核。
- 偵測訊號：使用者明確說在家中另一台執行，要求環境檢查、Log 及容易理解的步驟；走讀又發現檢查器依賴未安裝 Python、VC 試轉換依賴尚未建立模型。
- 預防規則：每一步列出已具備的前提與下一個具體操作。確認首次使用與接續使用不同路徑，將功能可執行與聲音品質分別驗收。
- 主動檢查：全文搜尋舊硬體假設與「先試轉換」「全部通過」等前置條件，走一次零環境、零模型、單片段試聽、失敗接續情境；核對圖與文字不強迫額外確認。
- 證據界線：Mermaid 節點／區塊檢查不代表視覺渲染成功；文件情境走讀不代表初學者實測通過。

## 2026-09-17：本機第一版與命令變數

- 類型：環境與實作範圍控制。
- 失敗模式：第一版若直接引入大型模型，會讓本機驗證被磁碟／GPU 條件卡住；另外 PowerShell 的 `$HOME` 是保留變數，不能拿來當暫存變數。
- 偵測訊號：使用者明確要求超過 4 GiB 的模型不要下載；測試命令曾因使用 `$home` 出現唯讀變數錯誤，改名後立即通過。
- 預防規則：先交付無模型的本機素材／WAV 垂直流程，模型接入必須經過大小政策；Shell 變數避開 `$HOME`、`$home` 等系統保留名稱。
- 主動檢查：測試模型政策的超限退出碼，並在 API 冒煙測試中確認首頁、專案、FFmpeg 探測及 WAV 輸出。
